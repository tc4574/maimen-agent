# 对话与回答展示修复（2026-10-24）

原因：旧版只显示最近6条消息，最多保存80条纯文本；查询结果只存在独立DOM区域，新查询会覆盖旧结果，刷新也无法恢复；API会话凭据只保存在内存。语音触发的新回答使上述问题更容易出现，但语音本身不应清空记录。

现改为本机独立对话：每个对话保存自己的消息、消息附带的查询结果/餐单快照、当前推荐轮次、选择、保留项和本机会话凭据。文字/语音共用同一个消息入口；新建对话分配新的后端会话，切换不会清空原对话。进行中的请求需先结束或取消再切换。模型最近上下文窗口与完整可见档案是两个概念。

活动等结果随对应回答保存为折叠附件，注明历史查询时间；新查询只追加。旧餐单可展开回看，价格仍按过期规则显示，不被重新标为当前有效。前端不再截断为6/80条，存储空间不足时显式提示保存失败。

历史旧版纯文本会迁移；旧版未保存的活动列表无法凭空还原，需要重新查询一次。保存位置是当前浏览器本地存储，不是云端跨设备同步。

回答采用安全的受限Markdown渲染（标题、加粗、强调、列表、代码）；原始HTML转义、链接仅显示文本。语音使用独立的纯文本转换，不读Markdown标记。未引入任意HTML渲染。

验证：6项Node测试通过，覆盖28项活动附件经过后续消息、重载与切换对话后的保留、旧记录迁移、HTML注入防护与Markdown/朗读转换，以及动画状态。真实麦克风设备验收仍需用户侧操作。
