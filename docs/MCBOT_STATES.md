# McBot 动画与接入边界

用户已明确：产品只做问答、数据查询、搭配推荐和收藏，不做下单、支付或订单闭环。旧设计中的订单扩展已取消。

## 动画逻辑

统一入口 `web/animation.mjs`，应用事件维护状态；不按时间随机切换业务表情。

| 状态 | 触发与结束 | 角色资源 |
| --- | --- | --- |
| 待机 | 无收音、播报、请求或临时反馈；首页文案“今日你‘麦’了吗？” | 02，现有角色轻动/眨眼 |
| 倾听 | 浏览器识别实际 onstart；onend 结束 | 03，好奇/专注 |
| 思考 | 推荐请求开始；成功、失败、取消等待后结束 | 30，思考 |
| 回应 | TTS 实际 onstart；结束、失败或停止播报后结束 | 10，开心回应；不是音素级口型 |
| 成功反馈 | 选中餐单或成功推荐 | 33/成功状态，最多1.6秒后恢复 |
| 需调整/错误 | 查询失败、无匹配结果 | 03，短暂关注状态；文字解释具体原因 |
| 暂停 | 页面隐藏 | 暂停动画；退出正在进行的语音会话 |

优先级：后台暂停 > 正在播报 > 正在收音 > 查询中 > 临时反馈 > 待机。优先级高的状态结束后回到仍然有效的低优先级状态。旧语音回调通过代次校验失效，停止播报不会取消数据请求。桌面鼠标仅影响视线，不改变业务状态；手机不要求悬停。减少动态效果模式暂停角色动画，并保留状态文字。

## 当前真实接入状态

后端已有麦当劳MCP适配器、六项只读推荐能力和本机Token读取。历史真实验收是2026-10-17，不代表今天重新验证。当前运行中的 `/api/capabilities` 返回 recommendations=false、conversation=false、campaigns=false；所以当前预览没有调用MCP获取新的业务数据。

真实推荐启用方式：项目根目录 `./scripts/start-web.ps1 -Live`。启用只表示允许发起查询，不能当作Token有效或MCP在线的健康检查。商品、营养、券、计价仍由后端查询，网页不持有MCP Token。

## 自由问答需要什么

用户选定模型服务商，并在本机私密配置模型API Key、API地址、模型名称（已有MODEL_API_KEY、MODEL_BASE_URL、MODEL_NAME占位项）。不要把Key贴在聊天里。模型应能稳定处理中文和结构化输出/工具调用；不需要因为问答另买一套麦当劳数据接口。

开发需补：后端模型适配器、会话上下文、有限工具路由、事实校验、超时/限流/用量上限，前端接真实回答与语音播报。仅填Key不会自动完成接入；网页也不会继承开发工具当前使用的模型账号。

## 上新查询需要什么

已发现的MCP工具 `campaign-calendar` 可查当月营销活动；可选specifiedDate有其特定三日邻近查询语义。需新增只读适配器、校验实际响应、解析活动日期/标题/文章、展示活动卡，并将明确的新品映射到门店菜单。

它不是完整的新品数据库。只有资料明确说明上新才标为新品；否则只称活动/在售商品。需要现有MCP Token仍有效且有该工具权限，尚需真实联调。固定“最近上新”入口可以先直接接这个查询，不必等待自由问答模型；模型用于后续自由追问与总结。
