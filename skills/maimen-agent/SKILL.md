# 麦门战争原型

本入口随完整项目使用。项目根目录位于本 Skill 文件夹的上两级，应包含 `maimen/demo.py` 和 `pyproject.toml`；若只有被单独复制的 Skill 文件，先定位完整项目。不要声称仅安装本文件就获得网页、模型或 MCP 权限。

## 运行

在项目根目录执行：

```text
python -X utf8 -m maimen.demo --db data/demo.sqlite3 --report artifacts/local/demo.json
```

这是自动脚本，依次执行选第二张、饮料换无糖、撤回、丢弃旧报价、收藏和模拟确认。运行后依据实际输出解释结果，并给出报告位置。

需要核验核心行为时执行：

```text
python -X utf8 -m unittest discover -s tests -v
```

## 能力边界

当前 `FixtureModel` 仅支持“选第二张”“饮料换无糖”“撤回上一步”，不是通用语言模型；其他自然语言不能假称已被理解或执行。演示餐品与价格全部虚构，模拟确认不会创建订单。

卡牌流程当前只有 `demo` 执行模式。独立真实连接检查使用已安装依赖的虚拟环境运行 `python -X utf8 -m maimen.mcp_probe --smoke`，只允许时间和营养查询。用户要求真实菜单或点餐时，明确完整餐单适配器尚未实现，不把演示值冒充官方结果。

## 修改与解释

解释架构时按需读取项目根目录的 `docs/PLAN_V1.md`；解释 MCP 进度时读取 `MCP_INTEGRATION.md`。实际能力以源码和运行结果为准。

修改核心时保留这些不变量：模型只提出允许的操作；卡片序号绑定输入时的场景；餐单变更使报价和确认失效；撤回恢复配方但不恢复旧报价；重复或迟到的结果不能覆盖当前状态；快照与事件原子提交。

用业务结果验证修改，不以页面文案或提示词是否包含特定句子替代行为测试。保持 demo 与未来 live 数据来源分离。
